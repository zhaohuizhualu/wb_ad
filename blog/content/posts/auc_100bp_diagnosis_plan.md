# AUC +100bp 攻坚：诊断框架与首轮验证计划

生成日期：2026-10-19
背景：UPE 优化周期结题（v31 收官 +2.90bp，详见 `upe_eval_compare_a/full_version_comparison.md`）。目标 AUC +100bp（0.865→0.875）才有上线 AB 显著收益。本文档记录诊断框架（两轮分析）与首批验证动作。

## 一、核心判断

**当前实验模式无法产出 +100bp。** 过去两个月的实验（UPE 五维度、SID 三轮、dropout、vecgate）全部收敛在 ±3bp——这不是运气差，是搜索空间本身的信号上限。+100bp 只可能来自未搜索区域的结构性缺口，不可能平均分布在全量样本上。

## 二、六个核心概念（工作纪律的六个侧面）

| 概念 | 一句话解释 | 本项目的具体映射 |
|---|---|---|
| 搜索循环 | 假设→实验→裁决→下一个假设的循环 | 两个月循环 10+ 轮，全部在 UPE 模块内部转圈，期望收益趋近零 |
| 搜索空间 | 所有可改动东西的全集 | 95% 实验落在 {模型结构×超参}；{样本}{标签}{容量}{优化器} 从未触碰 |
| 测量系统 | 判断改动好坏的整套工具链 | 逐窗差值 σ≈0.6bp，±3bp 结论部分可能来自测量噪声；train AUC 0.74~0.79 < eval 0.865 反常 |

## 三、大牛动作清单（对照本项目）

1. **审计迭代系统**：快评估 harness + 功效分析（σ=0.6bp 下，<3bp 假设 27 天链裁决置信度有限）；
2. **误差分解定位 headroom**：per-slice AUC / PAUC / GAUC（gauc_slot 已配置未使用）；0.865 均值下藏着 0.75 和 0.95 的切片，100bp 在盲区切片里；
3. **训练侧审计**：
   - 容量疑点：`embedding_size: 8`（50M 词表极端压缩）、`fcn: [128,128,128,32]`（2018 年配置）——emb 8→32 是已知 10~50bp 杠杆；
   - 反常疑点：train AUC 0.74~0.79 < 离线 eval 0.865（方向反常，正常应 ≥）；可能原因：per-batch 指标口径 / BN 训推不一致 / 增量链空转；
   - 优化器疑点：Adagrad + 小时级增量的累加器单调累积；
4. **标签与样本侧**：CPL 转化、正样本率 0.37%、train loss 全程不动——归因窗口、延迟反馈、曝光/位置偏差、极不平衡重采样。标签定义改 1% 等价于上千个模块实验；
5. **模块活性检查**：long-seq attention / PPNet / STAR 逐个验证"是否真的在工作"；v4 改写 attention target 侧但 history 侧不动这类设计决策需消融重验。

## 七、首批两个验证的结果（2026-10-19 完成）

### 验证 A：增量链参数移动量检查 —— 结论：**链在学习，未空转**（假设排除）

方法：v31 链相邻两 checkpoint（2026083015 step 2,337,299 → 2026083023 step 2,380,266，约 43k 步）逐变量组对比。checkpoint 已下载至 `/data0/huizhu1/retailer/tmp_ckpt_diff/`（6.8G，分析完可删）。

**A-1 参数移动量**：

| 变量组 | 相对移动 ‖Δθ‖/‖θ‖ | 判读 |
|---|---:|---|
| fm_v (embedding [50M,8]) | 1.15e-1 | 在动 |
| fm_w (线性权重) | 1.09e-1 | 在动 |
| deep_fcn | 2.99e-2 | 在动 |
| domain_bias/star | 2.06e-2 | 在动 |
| ppnet_gate | 1.70e-2 | 在动 |
| norm_stats (BN) | 4.62e-2 | 在动 |
| upe | 7.46e-3 | 在动（幅度最小） |
| attention(mhta) | 3.87e-3 | 在动 |

**A-2 Adagrad 累加器**（fm_v/Adagrad，50M×8）：median≈1e-4、p99≈1e-4、max≈20。**绝大多数 embedding 的累加器极小** → 有效学习率 ≈ lr/√acc ≈ 0.015/0.01 ≈ **1.5**（名义 lr 的 100 倍！）。担心方向反了：不是学习率衰减到零，而是**未被充分更新的参数学习率高达 1.5**——每次被梯度触达都会剧烈移动。这解释了：
- 每行 embedding 的中位相对移动 1.23e-2/小时（被触达行 p90 达 0.157）——**更新非常激进**；
- 50M 词表每小时被触达 54.3% 行（27M 行）——每小时一半词表被大幅更新一次。

**推论（重要）**：`initial_accumulator_value: 1e-4` + 稀疏触达使 embedding 处于"高方差跳跃更新"状态。**历史实验里 ±3bp 的波动，部分可能是这种训练噪声**，而非模型差异。这是测量系统问题的新证据——方向与原假设相反，但同样是"秤不准"的实锤。

### 验证 B：train AUC 反常核查 —— 结论：**口径不可比确认，BN 训推差异 + in-sample/out-of-sample 混杂，需补一个同数据对打实验**

事实链：
1. 训练日志的 `auc` 是 `tf.metrics.auc` 的**流式累计值**（证据：一小时内从波动 0.72→0.86 收敛到平滑的 0.791，与累计指标行为一致；单 batch AUC 模拟 std=0.2，与观测不符）；
2. 该值是 **TRAIN-mode 前向**（BN 用 batch 统计）在**当小时训练数据**上的 in-sample AUC ≈ 0.79；
3. 离线 eval 0.865 是 **EVAL-mode 前向**（BN 用 moving 统计，serving pb 导出）在**下一小时数据**上的 out-of-sample AUC；
4. 数据规模口径：train "hour" 标签实为 8 小时窗口（07/15/23 三段制，124M 样本/段 ≈ 15.5M/小时），eval 为单小时 15.2M——**每小时样本量恰好对齐**，排除"eval 样本太少太好测"的假说；
5. 两者差的 7.5pp 中：BN batch-stats vs moving-stats 差异、in-sample vs next-hour 差异的占比**未定**。

**关键未决问题**：7.5pp 的 gap 对相邻小时数据来说异常大（相邻小时近 iid，正常 out-of-sample 损失 <1pp）。两个候选解释：
- **BN 训推不一致**（batch stats 偏离 moving stats）→ 若成立，serving 用的 pb 与训练中的模型行为差异大，**线上预估质量可能被高估或低估**，需要修正；
- 训练数据与 eval instance 管道存在过滤差异（train_data_parquet vs output/instance 是两条管道）→ 需逐字段核对。

**决定性实验（待做，成本一次 streaming 推理）**：取 H 小时的 serving pb（已有），对 **H 小时自己的 train_data_parquet** 打分算 AUC。若 ≈0.79 → 纯 in/out-of-sample 差异（无害）；若 ≈0.865 → BN 训推差异是主因（需修 BN 或改训练口径）；若中间值 → 两者混杂，分别归因。

### 首批验证总结

| 疑点 | 结论 | 影响 |
|---|---|---|
| 增量链空转 | **排除**（参数在动） | 历史实验的收敛结果有效 |
| Adagrad 学习率衰减 | **反向发现**：稀疏参数有效 lr≈1.5，更新过激 | 训练噪声可能是部分"持平"结论的原因；后续实验建议试 initial_accumulator 1e-4→1e-2 或 Adam 一致化 |
| train AUC 0.79 vs eval 0.865 | 口径不可比（流式+BN+in-sample 三重混杂）；**BN 训推差异待定** | 若 BN 差异坐实，涉及 serving 校准；需同数据对打实验 |

**下一步优先级更新**：
1. 同数据对打实验（判 BN 训推差异）——一次 streaming 推理的成本；
2. Adagrad 累加器初始值消融（1e-4 vs 1e-2）——直接针对训练噪声，可能同时提升所有模型；
3. 之前的 slice 分解 / 掩码消融照计划推进。

### 8.3 2b 掩码消融（6 组净贡献）

| 掩码组 | slots | 全量净贡献 | 判读 |
|---|---|---:|---|
| **mm_sim 多模态相似度** | 1001 | **+1.23 pt** | 最大贡献者（仅 200 维 dense 输入） |
| **stat_counts 统计计数** | 600-644（45 slot） | **+1.11 pt** | 第二大，但为混合贡献待细分 |
| semantic 语义/频控/商品 | 973-975,46,47,507,508 | +0.39 pt | 中等 |
| user_profile 用户画像 | 31-35,50,145 | +0.07 pt | ≈零 |
| id_mem id 记忆 | 2,3 | +0.06 pt | ≈零 |
| behavior_seq 行为序列 | 820,821,512-515 | +0.04 pt | ≈零 |

**核心发现：**

1. **判别力高度集中在 mm_sim + stat_counts 两族**（合计 >2.3pt），其余四组全在噪声量级；
2. **behavior_seq ≈ 零贡献最意外**——attention/transformer 整套结构服务这些序列特征，掩掉 AUC 几乎不动。序列没学到东西，或信息已被 stat_counts 覆盖；
3. **id 记忆零贡献** —— 与验证 A 的 Adagrad 高方差更新发现互证：id embedding 未形成有效记忆，也解释 v31 单改写 deliver_id 增益有限；
4. **误差切片缺新信号而非新结构**：最大 headroom 切片（bucket3__70110011 AUC 0.705）掩掉 mm_sim 后掉到 0.689、70102027 场景掉 1.7pt——mm_sim 是这些切片的主要信息供给，但即便有它也只有 0.70-0.77，继续重组旧特征/加结构不会涨点；
5. **掩码普遍引起校准剧烈漂移**（stat_counts 掩掉全量校准 +3.9%→−1.1%，切片 ±20-50%）——预估分与特征供给强耦合、无校准层兜底。

### 8.4 下一步优化方向（按投入产出排序）

**P0：分切片校准层（零模型改动，直接吃掉线上损耗）**
- 事实基础：全量 +3.9% 系统性高估、冷启桶 +13.5%、多切片 ±10-50%；
- 方案：在预估出口加 per-(scene, bucket) 分桶校准（isotonic/Platt 或简单比值表），可用现有 cali 管道（cali_middle.py + ocpx_calibrate 文件机制）扩展分桶 key；数据用现成的 2a scored 缓存拟合；
- 预期：不动 AUC 的情况下修复线上计费/成本控制偏差，属于"免费"收益。

**P1：mm_sim 扩容（已验证的最大杠杆方向）**
- 事实基础：单特征组 +1.23pt，而输入只有 200 维 dense（mm_simscores_long）；
- 方案候选：a) 相似度信号源扩展（更多模态对、更细粒度）；b) 从 200 维统计量扩展为逐创意相似度序列（配合 attention）；c) 与 deliver_id 交叉（头部计划排序的抓手，见 P2）；
- 验证方法：扩容后重跑本实验的掩码管道看贡献增量。

**P2：高频计划排序（bucket3，37.6% 流量，AUC 0.815）**
- 这是 headroom 最大单元，但掩码显示现有特征在此切片贡献弱（stat_counts 仅小贡献）→ 需要**新信号**：出价/budget 上下文、同类目竞争强度、计划级时序（当日投放节奏）、历史 ECPM 反馈特征；
- 切入点：先做误差分析——bucket3 内部按 ps_id×opt 再切，确认 0.705 的 bucket3__70110011__86005003（9.4% 流量）是哪些计划在互排，读 50-100 条 hard case。

**P3：stat_counts 细分归因（一轮掩码，半天）**
- 45 slot 混合 +1.11pt：拆 600-620 / 621-644 两组重跑掩码，定位贡献集中度；若集中在少数 slot，这些是"小而关键"的特征，值得做特征工程强化。

**P4：behavior_seq 细分掩码 + 结构瘦身评估**
- 512-515（cpl 序列）与 820/821（长序列）分开掩；若细分仍为零，评估砍 attention 结构的计算节省（线上 RT 与资源）。

**P5：86007001 优化目标专项**
- AUC 0.755、正例率 0.05%：标签管道审计（延迟反馈归因窗口）优先于模型改动；该目标样本占比小（6.3%），可与 P0 校准层合并处理。

### 16.4 机制深化：累加器初始值与梯度量级的匹配关系（定量解释"为什么是 1e-6"）

起点是审计数据的一个细节：base23 累加器 p99 相对初始值只变动 0.69e-06（1.00e-06 → 1.69e-06）。
这个"小变动"蕴含了 1e-6 成为甜点配置的完整定量解释。

**梯度量级反推**：acc 增量 = 历史梯度平方和。15.4k 步区间触达 21.85M 行（43.7% 词表）
→ 单行平均触达 ~1 次。故单坐标梯度平方 ≈ 0.69e-06，即 **|g| ≈ 8.3e-04**。
embedding 梯度天然在 1e-4~1e-3 量级（链式法则稀释 + 正例率 0.25% 的 sigmoid 梯度 ≤0.25
+ batch 平均）。

**关键事实：梯度平方（~1e-6）恰好落在 1e-6 和 1e-4 两个初始值之间**：

| | base (1e-4) | base23 (1e-6) |
|---|---:|---:|
| 单次 g² 增量 / 初始值 | 0.7%（被淹没） | 70%（显著改变 acc） |
| 首触后有效 lr | 1.49（≈不变，恒定 1.5） | 11.5（衰减 23%） |
| 二/三次触达后 | 仍 ≈1.5（不退火） | ~9.4 / ~7.7（自动退火） |

- 1e-4 链：初始值是"噪声地板"，把 Adagrad 的自适应机制**关闭**了——有效 lr 恒定，
  与触达次数无关；
- 1e-6 链：初始值与真实梯度平方**同量级**——首次触达后即开始衰减，形成
  "前几次触达快学、之后自动减速"的退火曲线。**1e-6 是让 Adagrad 自适应真正
  启动的配置**，初始值从噪声地板变成了与数据匹配的先验；
- 由此定量解释 15.1 的观察：1e-5→1e-6 增益斜率收窄（+12→+7.6bp）——退火曲线
  头部（首触 15→11.5→9.4）的边际价值递减；1e-7（首触 47→~24→~17）头部更猛，
  过冲风险上升。

**一个风险量化（留给 full 掩码裁决）**：单次触达更新幅度 ≈ lr_eff × g：
- 1e-4 链：1.5 × 8.3e-4 ≈ 1.2e-3 ≈ 行范数（6e-4）的 2 倍；
- 1e-6 链：15 × 8.3e-4 ≈ 1.2e-2 ≈ 行范数（8e-4）的 **15 倍**。

即 1e-6 链的低频 id embedding 在单次触达后被"射"到由单样本决定的位置——记忆写进去了，
但可能写的是噪声（emb norm p99 ×4.2 的长大是双刃剑）。**裁决标准不变**：base23 full
掩码的 id_mem 显著上升 → 噪声也值；不升/降 → emb norm 长大是噪声累积，需在退火曲线
头部（如恢复略大的初始值 3e-6~1e-5 之间）找折中。

### 16.5 勘误与修正：16.4 的梯度反推存在分层混淆（从零开始的正确推导）

**你指出的问题成立。** 16.4 中"单行平均触达 ~1 次 → |g| ≈ 8.3e-04"的反推有错误：
它把 **p99 累加器坐标**（属于头部高频 id）错当成了**中位触达行**（长尾 id）来解方程。
以下是从零开始的完整推导，每个数字标注确切来源。

#### A. 基础量与物理含义

**fm_v**：50,000,000 行 embedding 表，每个 xfea 特征值占一行（8 维）。
**"触达"**：训练中某样本携带该特征值 → 该行收到一次梯度更新。同一行会被不同
样本反复触达（热门 id 在 47M 样本中出现数百万次；冷门 id 整个区间只出现一两次）。
**k**：某行在审计区间（15,372 步）内被更新的次数。

**流量核对**（训练侧参数）：47,227,035 样本 ÷ 15,372 步 = **3,072/步**
= batch 1536 × 2 GPU ✓（MirroredStrategy 每卡 1536）。

**审计观测**（drift per-row，来源标注）：
- 触达率 43.70% —— 50M 行中 21,852,142 行 k≥1（base23 段 per-row detail）
- 被触达行净移动 median **4.485e-5**（base23）/ **9.8e-6**（base）—— 同段
  "touched rows delta: median ..."
- 累加器 median **1.00e-6**、p99 1.69e-6、max 33（base23 lr 审计段）

净移动的中位数刻画"典型被触达行"——被触达行绝大多数是冷门 id（长尾），
所以 median 即长尾行的净移动。

#### B. 长尾行的自洽解（k=1 假设）

对典型长尾行：区间内被触达 1 次（长尾定义），更新基本未被抵消
（净移动 ≈ 单次更新幅度）：

    净移动 = lr_eff × |g|
    4.485e-5 = 15 × |g|          ← 15 = base23 有效学习率（lr 审计：eff-lr median=1.50e+01）
    → |g_med| ≈ 3.0e-6           ← 解出，非观测
    → g² ≈ 9e-12 ≈ 1e-11         ← 上式平方

**自洽性检验**（推导可信的关键）：
预测累加器终值 = 初始值 1e-6 + k×g² = 1e-6 + 9e-12 ≈ **1.00001e-6（不变）**
观测累加器 median = **1.00e-6（精确不变）** ✓ 一致。

**反例验证**（原 8.3e-4 为何必错）：若长尾行 g=8.3e-4，单次 g²=6.9e-7，
累加器应变为 1.69e-6 —— median 应是 1.69e-6，但实测 median 是 1.00e-6。
矛盾 → 8.3e-4 是把头部行（p99=1.69e-6 的坐标）的数字套给了长尾行。

#### C. 分层图景（各层独立自洽）

| 层 | 触达 k | 解法与证据 |
|---|---:|---|
| 长尾 id（触达行的主体） | 1-3 | 净移动 4.5e-5 → g_med≈3.0e-6；acc 增量 ~1e-11 可忽略，median acc 精确停在初始值 ✓ |
| 中频 id | 10-100 | acc 逐步累积，lr_eff 开始退火 |
| 头部 id（p99 坐标） | 数百+ | 增量 0.69e-6 = k·ḡ²，k~500 → ḡ≈3.7e-5（梯度更小但次数多） |
| 极端坐标 | acc_max=33 | 高频访问坐标，lr_eff 已降到 0.0026 |

#### D. 两条链的对照与机制结论

| 量 | base (1e-4) | base23 (1e-6) | 来源 |
|---|---:|---:|---|
| 长尾行有效 lr（恒定） | 0.015/√1e-4 = **1.5** | 0.015/√1e-6 = **15** | 长尾 g²=1e-11 撼不动初始值 → lr_eff 恒定 |
| 单次更新 = lr_eff × g | 1.5×3.0e-6 = 4.5e-6 | 15×3.0e-6 = **4.5e-5** | g 相同（梯度只差参数状态的 10% 量级） |
| 净移动实测 median | 9.8e-6 | 4.5e-5 | drift per-row |

理论比 10×，实测比 4.6×（base 中位行可能平均触达 2 次 + 部分抵消，量级正确）。

**机制结论**：占词表 98% 的长尾 id，其 g²（~1e-11）远小于任何初始累加器
（1e-4 和 1e-6 都是地板）→ 有效学习率恒定，1e-6 配置把长尾行每次更新放大
恒定的 10 倍 —— 这就是 4.6× 移动差异与 +19.9bp 的来源。头部 id 才是累加器
自适应真正退火的层。16.4 的"初始值与梯度量级匹配"表述修正为**分层匹配**：
长尾看比值（恒定 10×），头部看绝对量级（退火启动）。

#### E. 16.4 结论的修正清单

- ❌ 撤回：|g| ≈ 8.3e-04（头部/长尾混淆的产物）；
- ❌ 撤回："单次更新 = 行范数 15 倍"的风险量化 —— 用 g_med=3.0e-6 重算，
  base23 单次更新 ≈ 15×3.0e-6 = 4.5e-5 ≈ 行范数（8e-4）的 **6%**，完全正常，
  "写入单样本噪声"担忧基于错误量级，**降级为低风险**；
- ✅ 保留（强化）：1e-6 收益主体在长尾行（恒定 ×10 步长）；50M 词表 98% 是
  长尾行 → full 掩码的 id_mem 归因预期更乐观，且若成立，受益切片应集中在
  低频桶（可在掩码分桶表中直接验证）。

### 20.2 三个裁决性结论

1. **id_mem 归因：+19.9bp 不是来自 id 记忆**。id_mem 掩码贡献 base23=0.05pt vs
   base=0.07pt，不升反微降——16.4/16.5 节"embedding 更快形成记忆"的假设被证伪。
   emb norm ×4.2 的长大（16.1）确实存在，但长大的是**噪声/方向性分量而非可掩码
   检出的排序信号**（掩掉 cust_uid/deliver_id 的 embedding 输入，模型行为几乎不变，
   说明 FM/DNN 并没有真正依赖这些 embedding 行）；
2. **真实机制：特征间冗余吸收（entanglement）**。单组边际贡献几乎全线缩水
   （mm_sim 腰斩、ucoec -40%、att_seq/sg_seq -35%），但总信息量持平（35.3 vs 36.3）
   且总 AUC 更高——**1e-6 的高学习率让模型把各组特征的信息更深度地交织在一起**，
   单独抽掉任何一组，其余组能补位（冗余↑），Σ/总信息从 67% 降到 56% 直接量化了
   这一点。增益来自"更分布式、更鲁棒的表征"，而非某个特定信号源变强；
3. **例外组**：ad_object 几乎不缩（0.94×）、ad_tag_stream 轻缩（0.91×）——841/原生
   对象 id 的信号在高学习率下依然独立支撑；user_seq_act/session 反而放大（小绝对值）
   ——行为序列类在高 lr 下边际贡献上升，与 16.1 的 ppnet_gate 移动 3× 呼应。

### 20.3 对路线的影响

1. **R6 收敛定论**：1e-6 的收益机制 = 更高 lr 下的分布式表征（冗余吸收），不是 id 记忆。
   16.5 节"长尾行 ×10 步长 → 记忆"的推理链在"移动量"一层成立、在"排序信号"一层不成立——
   emb 长大了但长的是噪声。**1e-7 臂的预期需要下调**（机制不是记忆形成，继续放大 lr
   的边际收益存疑），且高 lr 的冗余吸收也解释了为何 1e-5→1e-6 增益斜率收窄；
2. **16.2 节 ppnet_gate 竞争解释同样存疑**——ppnet 相关组（user_profile 0.64×、
   user_context_cross 0.85×）贡献也未上升，ppnet 移动 3× 同样是"动了但没转化为
   独立信号"；
3. **对 R2-R4 特征供给侧是利好**：新特征（deliver 统计等）进 1e-6 模型后会被更快地
   编织进表征（学得更快），但**其独立贡献也更难通过掩码检出**（冗余吸收）——
   特征价值评估应以"加了之后全量 AUC 变化"为主判据，掩码贡献为辅；
4. 基线锚点：base23 的特征价值地图与 base 结构一致（前二仍是 context/ad_tag_stream，
   841 仍是王），**第十九节的结论在新学习率下依然成立**。

2. **操作价值（瘦身而非精度）**：删 6 slot 的精度代价 ~1bp（噪声级），换来的是

4. **一个待解释的小信号**：self AUC 均值 +0.8bp 但中位 −1.4、8/23 胜——方向
   不一致，且幅度在噪声内，不足以支撑"删除 id 对冷启有益"的解读；若后续窗口
   （≥3 周）self 侧出现稳定正向，再回头分析（可能与 id_mem 掩码在 self 维度的
   贡献分解有关）。

### 23.4 方法论注记

本实验与掩码消融形成"双验证"结构：掩码（推理期、冻结模型、单组边际）+
删除（训练期、重训练、允许重分配）。两者结论一致时（本例），结论可信度显著
高于单一方法——掩码的"分布偏移伪影"疑虑和删除实验的"重训练噪声"疑虑互相
抵消。后续对大贡献组（如 841）的处置决策前，建议同样做双验证。

## 二十四、"周期性全量重训 + 增量微调"实施方案（2026-10-23 设计稿）

背景：del_adid（23 节）+ 十六/二十节证明增量链上 id 记忆无法形成（触达密度不足 +
数据非 iid + 优化器状态路径依赖）。本节给实施设计。**基础设施盘点：现有管道已具备
大半能力**——增量循环已内置 batch_model 恢复机制（run_incr_model_window_gpu.sh:167-193，
batch.model.done 标志 + 检测到即切换 batch 基座），/day/ 目录结构存在，restore_hook
已支持 include_patterns 按变量名过滤恢复（hooks.py，方案 B 的关键依赖）。

### 24.1 两个方案变体

**方案 A：周期性全量重训（重但彻底）**

```
每 N 周（建议 2-4 周起步）：
  1) 离线全量 job：取最近 W 天全量样本（建议 W=30~60，与增量窗口对齐），
     shuffle 训练 E epoch（建议 E=3-5），从零初始化（不是从增量链续训——
     全量重训的价值就是打破增量链的路径依赖，从增量链热启动会继承其偏差）
  2) 产出 batch model：写到 ${base_op_dir}/day/<date>/train_model +
     batch.model.done.<date> 标志（现有格式，增量循环自动识别）
  3) 增量链切换基座：下一小时的增量任务 restore 自 batch model
     （is_batch_update 分支已有现成逻辑），继续天级滚动
  4) 增量继续滚 N 周 → 下一次全量重训
```

- 训练配置：与增量链同 yaml（同优化器/学习率），但 max_epochs>1、全量 shuffle；
- 成本：30 天 × ~120M 样本/天 × 3 epoch ≈ 100 亿样本触达，单次约 1-2 天 GPU 时；
  每 2-4 周一次 ≈ 常态训练成本的 5-15% 增量；
- 风险：全量模型与增量模型的"近期分布适应"有断层（全量平均 vs 增量追新），
  切换后前 1-2 天 AUC 可能短暂回落再恢复——需要灰度观察。

**方案 B：id embedding 离线预热（轻量，只修 id 记忆）**

```
每周一次（频率可高于方案 A）：
  1) 离线 job：取最近 W 天全量样本，从当前增量链 checkpoint 热启动，
     但只训练 id 类变量（fm_v 中 id 相关行）—— restore_hook 的
     include_patterns 限定 ["fm_v"] + train_op 只更新该 scope
     （需小改 trainer：var_list 传入 optimizer）
  2) 更直接的做法（推荐）：不训练，直接【统计回写】——离线从全量数据算出
     每个 deliver_id 的半长期统计（pv/ctr/ctcvr），直接写入其 embedding 行
     （用统计值 × 投影初始化），跳过"靠梯度学记忆"这一步
  3) 回写后的 embedding 表作为增量链下一小时的 restore 源
```

- 方案 B-1（梯度预热）：与方案 A 同机制但范围小，成本低一个量级；
- **方案 B-2（统计回写，推荐首选验证）**：与 R2（adid 统计特征）殊途同归——
  区别只是信息进入模型的方式（embedding 初值 vs 特征列）。B-2 其实可以用
  R2 的特征方案先验证信息价值，再决定要不要做 embedding 回写的工程。

### 24.2 实施步骤（按验证顺序）

**Step 1（先做，零风险）：一次性全量重训对照实验**
- 用 cpl_ctr_base 的现有数据（0804-1030，约 8 周）做一次全量重训（方案 A 的
  单次执行），产出 cpl_ctr_batch_v1；
- 对比三件事：a) 全量 AUC vs 增量链同窗口；b) **id_mem 掩码贡献**（预期从
  0.07pt 显著上升，若到 1pt+ 则触达密度假设实证）；c) 1e-6 vs 1e-4 在全量
  训练下的差异（十六节的机制在全量下应消失——累加器正常累积）；
- 这一步同时是方案 A 的可行性验证和"流式 vs 全量"理论的实证检验（23.6 节
  思想实验的落地）。

**Step 2：周期机制接入（Step 1 验证通过后）**
- 全量 job 脚本化 + crontab（或手动触发），产出 batch model 到 /day/ 路径；
- 增量循环无需改动（batch_model 检测逻辑已存在）；
- 切换时的 AUC 监控：对比切换前后 48h 的逐窗 AUC，回落 >5bp 则回退上一基座。

**Step 3（可选）：B-2 embedding 统计回写**
- 仅当 Step 1 显示 id 记忆价值大（>1pt）但方案 A 的全量重训成本不可接受时；
- 依赖：离线统计管道（R2 的 stats 表可复用）+ embedding 行回写工具
  （checkpoint 编辑，TF1 下需写定制 Saver，工作量约一周）。

### 24.3 与现有路线的合并

- **R2（adid 统计特征）与本方案是同一问题的两条解法**：特征侧（外挂统计列）
  vs 训练侧（重训/回写恢复记忆）。Step 1 的 id_mem 结果直接裁决两者的优先级：
  id 记忆价值 <1pt → R2 特征侧足够（信息本来就少）；1-3pt → 两条都值得，
  R2 先行（工程简单）；>3pt → 训练侧优先（信息量大到特征列装不下）；
- 20 节的"1e-6 增益衰减"问题同时被方案 A 缓解：周期性重训把早期塑形的好处
  定期固化，增量阶段始终处于"新鲜"窗口内，衰减不再累积；
- bhv_v2（-1 修复版）与此正交，按原计划并行。

### 25.6 bhv 系列终局判读

三重证据链（v1 −4.5bp 20 窗、v2 修复版 −6.0bp 12 窗、数据管道核查无误）下，
deliver 统计特征**外挂列路线判负**。机制层面的两个候选解释（无法从当前数据
区分，供后续参考）：

1. **20 节"冗余吸收"的负面推论**：增量链上模型把新列的信息快速编织进已有
   表征（1e-4 下相对慢、但仍发生），单列信息被稀释到无法形成独立排序能力，
   同时新列的噪声（6h 窗口统计噪声、三窗口共线）进入主干反而劣化；
2. **特征本身与现有信号冗余**：adid 统计与 sg_deliver_id_seq（行为序列）、
   cust_uid/feed_id 的 embedding、841 语义码高度相关——第 22.3 节显示冷启侧
   确有信号空洞，但空洞的成因可能是"冷启样本太少模型学不动新列"而非
   "缺信息源"。

**处置决定**：特征侧 bhv 系列止损（v2 链可停），R2 的 open question 移交
24 节 Step 1（全量重训对照实验）——它将在"训练充分"（消除触达密度瓶颈）的
条件下重测 id/统计信息的价值，是特征侧 vs 训练侧路线的最终裁判。
